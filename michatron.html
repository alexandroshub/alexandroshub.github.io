Autonomous Guided Vehicle

Ένα Arduino-based mobile robot με autonomous navigation, line-following και obstacle avoidance. Full mechatronics integration, από sensor fusion μέχρι motor driver control. Χωρίς off-the-shelf stack, όλα custom.

01 — The Problem

Τι έφτιαξα και γιατί;

Το AGV (Autonomous Guided Vehicle) ήταν το πρώτο μου ολοκληρωμένο mechatronics project. Στόχος: ένα robot που μπορεί να κινείται αυτόνομα σε έναν χώρο, να ακολουθεί γραμμή, να αποφεύγει εμπόδια, και να σταματάει με ασφάλεια — χωρίς τηλεχειρισμό, χωρίς GPS, χωρίς cloud.

Το πρόβλημα ήταν απλό αλλά βαθύ: πώς παίρνεις raw sensor data και το μετατρέπεις σε απόφαση κίνησης σε πραγματικό χρόνο, πάνω σε constrained hardware (Arduino Uno, 16MHz, 2KB RAM).

Ο στόχος σε μία πρόταση

Ένα αυτόνομο robot που ακολουθεί γραμμή και αποφεύγει εμπόδια, χρησιμοποιώντας μόνο Arduino και απλούς sensors — χωρίς εξωτερικό υπολογιστή.

03 — Approach

Πώς το έφτιαξα;

Η αρχιτεκτονική είναι reactive: sensors → microcontroller → actuators. Δεν υπάρχει planning — μόνο άμεση αντίδραση σε input. Αυτό είναι το κατάλληλο για ένα AGV με περιορισμένους πόρους.

Key decisions

  • Reactive control αντί για state machine — λιγότερο code, πιο γρήγορη απόκριση. Για line-following, το state machine δεν προσφέρει τίποτα.
  • IR array αντί για camera — η camera θα απαιτούσε Raspberry Pi. Τα IR sensors κάνουν τη δουλειά με 1/100 του κόστους.
  • Sensor fusion: IR + Ultrasonic — τα IR για γραμμή, τα ultrasonic για εμπόδια. Κάθε sensor κάνει ένα πράγμα καλά.
  • PWM motor control — αντί για on/off, χρησιμοποιώ PWM για smooth acceleration και turning.

Code highlight

Το πιο ενδιαφέρον κομμάτι είναι το line-following logic. Χρησιμοποιεί 3 IR sensors (left, center, right) και αποφασίζει κατεύθυνση:

// Line following — 3 IR sensors
#define IR_L 2
#define IR_C 3
#define IR_R 4

void followLine() {
  bool L = digitalRead(IR_L);
  bool C = digitalRead(IR_C);
  bool R = digitalRead(IR_R);

  if (C && !L && !R) {
    // Κέντρο: ευθεία
    motorForward(180, 180);
  }
  else if (L) {
    // Αριστερά: στρίψε αριστερά
    motorForward(80, 180);
  }
  else if (R) {
    // Δεξιά: στρίψε δεξιά
    motorForward(180, 80);
  }
  else {
    // Χάθηκε η γραμμή: σταμάτα
    motorStop();
  }
}
Γιατί 3 IR sensors

Ένας sensor θα ήταν αρκετός για ευθεία, αλλά όχι για στροφές. Τρεις δίνουν direction awareness χωρίς πολυπλοκότητα.

05 — What Failed

Τι δεν δούλεψε;

Εδώ κερδίζεις credibility. Όλοι έχουν αποτυχίες — λίγοι τις παραδέχονται.

❌ Failure #1: IR sensors και ambient light

Τα IR sensors ήταν ευαίσθητα στο φως του δωματίου. Σε φωτεινό περιβάλλον, το line-following ήταν ασταθές. Λύση: Πρόσθεσα calibration routine στο startup — το robot διαβάζει το "μαύρο" και το "άσπρο" και προσαρμόζει τα thresholds. Μάθημα: Πάντα calibrate τους sensors στο περιβάλλον που θα τρέξουν.

❌ Failure #2: Motor driver υπερθέρμανση

Το L298N ζεσταινόταν πολύ όταν οι μοτέρ δούλευαν συνεχώς. Σε 10 λεπτά λειτουργίας, η απόδοση έπεφτε. Λύση: Πρόσθεσα ψύκτρα και μείωσα το duty cycle (max 180/255 αντί για 255/255). Μάθημα: Τα motor drivers δεν είναι ιδανικά — πάντα υπολόγισε thermal budget.

❌ Failure #3: Battery voltage drop

Όταν οι μπαταρίες έπεφταν κάτω από 6V, το Arduino έκανε reset στη μέση της κίνησης. Λύση: Πρόσθεσα voltage divider + read στο loop, και το robot σταματάει ομαλά όταν η τάση πέσει κάτω από 6.2V. Μάθημα: Πάντα παρακολούθησε την τροφοδοσία — ειδικά σε battery-powered projects.

07 — Lessons

Τι έμαθα;

  1. Οι sensors είναι πιο σημαντικοί από τον κώδικα. Ένας καλός sensor με μέτριο code δουλεύει. Ένας κακός sensor με τέλειο code δεν δουλεύει.
  2. Πάντα calibrate. Τα IR sensors, τα motors, τα thresholds — όλα αλλάζουν ανάλογα με το περιβάλλον. Ένα calibration routine στην αρχή σώζει ώρες debugging.
  3. Το hardware έχει όρια. Το L298N ζεσταίνεται, οι μπαταρίες πέφτουν, το Arduino κάνει reset. Πάντα σχεδίασε για αυτά τα όρια, όχι γύρω από αυτά.
